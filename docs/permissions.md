# 권한 모델 (Permissions)

> 확정: 2026-08-14 · 결정 기록: [decisions/0003](decisions/0003-two-layer-permission-model.md)

## 1. 두 층 구조

권한은 "등급"이 아니라 "범위"로 나눈다. 서로 다른 축의 정보 두 개를 따로 저장한다.

| 층 | 저장 위치 | 값 | 의미 |
|---|---|---|---|
| 전역 역할 | `User.global_role` | `ADMIN` / `MEMBER` | 동아리 임원인가 — **사람에게** 붙는 속성 |
| 분반 역할 | `Enrollment.role` | `OPERATOR` / `STUDENT` | **이 분반에서** 무엇인가 — 사람–분반 **관계에** 붙는 속성 |

교육 운영진을 전역 등급으로 만들지 않는 이유:

- 분반은 학기마다 자원자가 있어야 열리고, 같은 사람이 C반에서는 운영진·Spring반에서는 수강생일 수 있다. "이 사람은 교육 운영진인가?"에는 답이 없고 "**이 분반의** 운영진인가?"에만 답이 있다.
- 전역 슈퍼유저로 묶으면: 남의 반 과제를 조작할 수 있고, 학기가 끝나도 권한이 남으며, 매 학기 명단 정리 작업이 생긴다 (최소권한 원칙 위반).
- 분반에 묶인 OPERATOR는 분반을 보관 처리하는 순간 자동으로 효력을 잃는다. 권한 회수를 아무도 기억할 필요가 없다.

## 2. 판정 순서 — 모든 API 공통

1. 로그인했는가 → 아니면 `401`
2. `global_role == ADMIN`인가 → 맞으면 **통과** (임원은 모든 분반에서 운영자 이상)
3. 해당 분반에 대한 Enrollment이 있는가 → 없으면 `403`
4. `Enrollment.role`이 API 요구 수준을 만족하는가 → 아니면 `403`

이 4단계는 공통 컴포넌트(어노테이션) 하나로 구현해 모든 API에 붙인다. 개별 API에서 권한 로직을 따로 짜지 않는다. 고위험 영역이므로 PM이 직접 구현한다.

## 3. 권한 매트릭스

| 기능 | 임원진<br>(전역 ADMIN) | 교육 운영진<br>(그 분반 OPERATOR) | 교육생<br>(그 분반 STUDENT) | 미소속 부원 |
|---|---|---|---|---|
| 분반 생성·보관, 운영진 지정 | ✅ | ❌ | ❌ | ❌ |
| 수강생 배정·제외 | ✅ 모든 반 | ✅ 자기 반 | ❌ | ❌ |
| 과제 CRUD·마감 설정 | ✅ | ✅ | ❌ | ❌ |
| 제출물 전체 열람·미제출 대시보드·리뷰 작성 | ✅ | ✅ | ❌ | ❌ |
| 과제 열람·제출 | ✅ | ✅ | ✅ | ❌ |
| 본인 제출 기록·리뷰 열람 | — | — | ✅ 본인 것 | ❌ |
| 분반 목록 보기 | ✅ | ✅ | ✅ | ✅ (미소속 안내) |
| (P3) OJ 문제 출제 | ✅ | ❌ | ❌ | ❌ |
| (P3) OJ 문제 풀이 | ✅ | ✅ | ✅ | ✅ |

## 4. 분반 생성과 부트스트랩

- 분반 생성·보관, OPERATOR 지정: **전역 ADMIN 전용.** OPERATOR는 분반이 있어야 존재할 수 있으므로, 분반을 만드는 권한은 전역일 수밖에 없다.
- "강사 자원" 절차는 시스템 밖(동아리 의사결정)에서 일어나고, 시스템은 결과만 기록한다: ADMIN의 분반 생성 화면에서 이름·설명·운영진 지정을 한 번에 처리 (UC-A1).
- **최초 관리자(부트스트랩)**: 첫 배포 시 DB에 수동으로 `global_role = ADMIN` 지정. 절차는 운영 문서에 기록한다.

## 5. 수강생 배정과 명부 연동

- P1: 운영진이 직접 배정한다. 학생 신청 → 승인 흐름은 P1 제외 ([decisions/0004](decisions/0004-p1-scope-exclusions.md)).
- "명부에서 체크리스트로 배정" UX는 홈페이지가 **회원 명부 조회 API**를 제공할 때 가능하다. 로그인 연동(신원 확인)과는 별개 기능이다.
- 준회원/정회원 등 회원 상태의 source of truth는 홈페이지. HOJ는 읽어서 표시만 하고 저장하지 않는다 (이중 저장 = 불일치).

## 6. OJ 모드 (P3)

- OJ 문제 = `cohort_id NULL` + `deadline NULL` + 자동채점인 Assignment.
- 출제: 전역 ADMIN 전용 (분반이 없으므로 OPERATOR 개념이 성립하지 않는다).
- 풀이: 로그인한 부원 전체 — 분반 미소속 포함.
