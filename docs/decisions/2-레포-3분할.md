# 2. 레포 3분할 (docs / frontend / backend)

- 날짜: 2026-08-14 · 상태: 확정

## 배경

- 초기: 모노레포(backend/·frontend/)로 시작
- 팀 3인 확정(PM+FE+BE 겸 1, BE 주니어 1, 디자이너 1) 후 구조 재검토

## 결정

1. 기존 레포를 `haedal-online-judge-docs`로 rename — 기획·설계·결정 기록의 본진(대문)
2. `haedal-online-judge-backend`, `haedal-online-judge-frontend` 신규 생성

## 근거

- 문서가 이미 기존 레포에 존재 → 이관 비용 ≈ 0, rename은 히스토리·리다이렉트 보존
- 문서 소유권: 특정 코드 레포에 비종속 — 중립 확보. 디자이너의 활동 무대 확보
- 인수인계 시 "여기부터 읽으세요"라고 지목할 대문 확보

## 운영 규칙

- API 명세: backend(springdoc 자동 생성)가 본진 — docs에 복사 금지, 링크만
- 이슈: 코드 작업은 각 코드 레포, 기획·결정·디자인·온보딩은 docs 레포
- 옛 이름(`haedal-online-judge`)으로 새 레포 생성 금지 (리다이렉트 보호)
