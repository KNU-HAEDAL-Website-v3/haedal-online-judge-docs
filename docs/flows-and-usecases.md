# HOJ 플로우 & 유스케이스 (P1)

> 기준: 레이아웃 v2.1 (2026-08, 학생 흐름 5화면) + `docs/mvp-scope.md`
> 화면(레이아웃)과 코드(API·도메인) 사이의 다리 - 플로우의 분기 = 코드의 if, 유스케이스의 예외 = 에러 처리 목록.

## 0. 레이아웃 v2.1 반영 메모

| 수정 | 반영 |
|------|------|
| 분반명 예시 "2026-2 C언어" | 분반 이름은 자유 텍스트(언어·과목 기반 명명). 모델 변경 없음 |
| 회원가입 → "해달 홈페이지 리다이렉션(?)" | 링크로 처리 (HOJ가 계정을 만들지 않는 원칙 유지). 홈페이지 가입 URL 확정 필요 → 3절-10 |
| "지각 제출(지각은 생각해보기)" | **지각 정책 자체가 미결로 격상** → 3절-1. 아래 플로우는 양 갈래 모두 표기 |
| "추후 슬롯 (P1 미노출)" 마커 삭제됨 | 의도 확인 필요 - P1에 보여줄 거면 비활성 상태 디자인이 필요해짐 → 3절-9 |

## 1. 플로우차트

### 1.1 학생 메인 플로우 (화면 이동)

```mermaid
flowchart TD
    A["HOJ 접속"] --> B{"로그인 상태?"}
    B -->|아니오| C["해달 홈페이지 로그인으로 이동\n(returnTo: 원래 목적지)"]
    C --> D["로그인 후 HOJ 복귀"]
    B -->|예| E["홈 - OOO님 환영합니다"]
    D --> E
    E --> F{"소속 있음?"}
    F -->|없음| G["미소속 안내 문구"]
    F -->|있음| H["분반 페이지 - 차시 목록 + 마감"]
    H --> I["차시 페이지 - 과제 카드 + 상태 배지"]
    I --> J["과제 페이지 - 명세 · 제출란"]
    J --> K{"제출 타입"}
    K -->|코드| L["코드 작성 · 언어 선택"]
    K -->|파일| M["파일 첨부"]
    L --> N["제출하기"]
    M --> N
    N --> O["제출 판정 (1.2절)"]
    O --> P["내 제출 기록 갱신 · 배지 변경"]
    P --> J
```

### 1.2 제출 판정 (서버 로직)

```mermaid
flowchart TD
    A["POST /submissions"] --> B{"로그인 세션 유효?"}
    B -->|아니오| X1["401 - 로그인 이동\n프론트: 작성 코드 유지"]
    B -->|예| C{"해당 분반 소속?"}
    C -->|아니오| X2["403 거부"]
    C -->|예| D{"입력 검증\n코드: 길이 / 파일: 확장자·크기"}
    D -->|실패| X3["400 - 에러 표시\n작성 내용 유실 금지"]
    D -->|통과| E{"마감 전?"}
    E -->|예| F["저장 - 상태: 제출 완료"]
    E -->|아니오| G{"지각 허용 과제?\n※ 정책 미결 (3절-1)"}
    G -->|예| H["저장 - 상태: 지각 제출"]
    G -->|아니오| X4["422 거부 - 마감 안내\n프론트: 버튼 사전 비활성"]
    F --> I["최신 제출을 대표로 기록"]
    H --> I
```

- 마감 판정 시각: **서버 수신 시각** 기준 (클라이언트 시계 불신). 저장은 UTC, 표시는 KST
- 재제출: 무제한(가안). 같은 과제의 기존 제출은 이력으로 보존, 최신이 대표

### 1.3 운영진 플로우

```mermaid
flowchart LR
    A["분반 생성"] --> B["부원 등록\n(명단 붙여넣기)"]
    B --> C["차시 단위 과제 일괄 등록\n(타입 · 마감)"]
    C --> D["학생 제출 발생"]
    D --> E["현황판 - 제출/미제출/지각"]
    E --> F["미제출 명단 확인"]
    E --> G["제출물 열람\n코드 뷰 / 파일 다운로드"]
```

## 2. 유스케이스

### 2.1 액터

| 액터 | 정의 | 권한 근거 |
|------|------|-----------|
| 학생 | 분반에 student로 등록된 부원 | `Enrollment.role = student` |
| 운영진 | 분반 운영 권한자 | `Enrollment.role = operator` |
| 관리자 | 시스템 전체 관리 (Root) | `User.global_role = admin` |
| 해달 홈페이지 | 외부 시스템 - 인증·계정 담당 | 연동 방식 미확정 |

### 2.3 상세 명세 (핵심 2건)

#### UC-S4 코드 제출

| 항목 | 내용 |
|------|------|
| 액터 | 학생 |
| 사전조건 | 로그인 상태, 해당 분반 소속, 과제 타입 = 코드 |
| 기본 흐름 | ① 과제 페이지 진입 ② 언어 선택 ③ 코드 작성 ④ 제출하기 ⑤ 서버 판정(1.2절) ⑥ "제출 완료" 배지 및 기록 갱신 |
| 대체 흐름 | A1. 마감 후 + 지각 허용 → "지각 제출로 기록됩니다" 안내 후 진행, 상태=지각 제출 |
| 예외 흐름 | E1. 세션 만료 → 401, **작성 코드는 화면에 보존**, 재로그인 후 이어서 제출<br>E2. 미소속 분반 URL 직접 접근 → 403<br>E3. 마감 후 + 지각 비허용 → 제출 버튼 사전 비활성 + 마감 안내<br>E4. 제출 버튼 연타 → 처리 중 버튼 잠금, 서버 중복 방지<br>E5. 코드 길이 초과 → 400, 작성 내용 유지 |
| 사후조건 | Submission 1건 추가, 해당 과제의 대표 제출 갱신 |

#### UC-O3 차시 단위 과제 일괄 등록

| 항목 | 내용 |
|------|------|
| 액터 | 운영진 |
| 사전조건 | 해당 분반의 operator |
| 기본 흐름 | ① 분반 선택 ② 차시 번호·마감 일시 입력 ③ 과제 N개 입력(이름·설명·명세·타입) ④ 등록 ⑤ 학생 분반 페이지에 차시 노출 |
| 대체 흐름 | A1. 기존 차시에 과제 추가 등록 |
| 예외 흐름 | E1. 마감이 과거 시각 → 경고 후 확인 요구 (의도적 소급 등록 허용 여부는 확인창으로)<br>E2. 등록 후 마감 수정 → **기존 제출의 지각 재계산 정책 미결 (3절-2)**<br>E3. 타 분반에 등록 시도 → 403 |
| 사후조건 | week=N인 Assignment N건 생성 (마감 동일) |

## 3. 새로 드러난 결정 · 보완 항목

- 이번 플로우·유스케이스 작성에서 도출
- ⚖ = decision 이슈 등록 대상, 🔧 = 구현 시 처리

| # | 항목 | 내용 |
|---|------|------|
| 1 ⚖ | **지각 정책** (레이아웃 메모 "생각해보기") | 선택지: ①마감 후 완전 차단 ②전 과제 지각 허용+표시 ③**과제별 선택** - 모델의 `allow_late` 필드가 이미 ③ 구조. 차단이 필요한 과제(시험형)와 받아주는 과제가 공존 가능하므로 ③ 권고 |
| 2 ⚖ | 마감 수정 시 지각 재계산 | 마감 연장 시 이미 "지각"인 제출을 소급 구제할 것인가. 권고: 재계산(연장 = 구제 의도가 일반적) |
| 3 ⚖ | 파일 제한 | 허용 확장자 화이트리스트 · 최대 크기(예: 20MB). 온프렘 디스크 보호 목적. 심화반 과제 형태(zip?) 확인 후 확정 |
| 4 🔧 | 작성 내용 유실 방지 | 모든 제출 실패(401·400·422)에서 프론트가 코드/첨부 상태 유지. 세션 만료가 최다 시나리오 |
| 5 🔧 | 중복 제출 방지 | 처리 중 버튼 잠금 + 서버 측 연속 요청 방어 |
| 6 🔧 | 권한 밖 URL 직접 접근 | 일괄 403 → 홈 리다이렉트 + 안내. 분반·차시·과제·제출물 전 리소스 공통 규칙 |
| 7 ⚖ | 운영진 권한 부여 체계 | operator 지정은 관리자(Root)의 일 - UC-A1. **최초 관리자는 DB 수동 지정**(부트스트랩) 문서화 필요 |
| 8 ⚖ | 과제 삭제 정책 | 제출물 딸린 과제 삭제 시: 하드 삭제 금지, 숨김(soft delete) 권고 - 제출 이력은 증빙 |
| 9 ⚖ | 홈 "추후 슬롯" P1 노출 여부 | v2.1에서 미노출 마커가 빠짐. 보여줄 거면 비활성 카드 디자인 필요, 숨길 거면 마커 복원 |
| 10 🔧 | 회원가입 리다이렉션 | 홈페이지 가입 페이지 URL 확정 → 링크 연결 (홈페이지팀 협의 항목에 추가) |
